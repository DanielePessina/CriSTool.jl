Running simulations ​

julia
using CriSTool

crystal_model = CrystallisationModel(LysozymeSystem();
    nucleation = CNTNucleation(ln_nucleation_prefactor = 38.0, surface_energy = 0.0006),
    growth = EmpiricalGrowth(growth_coefficient = 1e-9 / 60, growth_order = 3.0))

batch_run = RunConditions(temperature = 293.15, concentration = 18.0)
trajectory = simulate(crystal_model, batch_run; solver = MoM(), saveat = 0.0:3600.0:28800.0)
trajectory.success
trajectory.concentration[end]
trajectory.d43[end]

A model contains the material system and the bound kinetic laws. A law called with all of its parameter names returns a bound KineticModel; CNTNucleation() alone is the unbound law, and a partial set of names is an error. Keywords that name a law's configuration fields (for example Lref on EmpiricalLengthGrowth) configure the law instead of binding a parameter. Read named values through crystal_model.growth.parameters.

RunConditions(; temperature, concentration, solvent=(;), crystals=nothing, operation=BatchOperation()) holds everything else about one run. A numeric temperature is Kelvin and becomes a ConstantTemperature; any AbstractTemperature is accepted. merge(conditions; concentration = 20.0) returns a copy with the named settings replaced. simulate returns the solution without the input problem. Always inspect trajectory.success before interpreting outputs.

For another material, supply a CrystallisationSystem(saturation_model=..., crystal_density=..., volume_shape_factor=...). Molecular volume may be nothing when unused; CNT requires it and fails explicitly if it is missing.

Inspecting objects ​

Conditions, seeds, solvers, operations, models, solutions, fits, inference results and predictions print a short summary at the REPL. Containers and repr use a one-line form. Sizes are stored in metres and displayed in µm; FromObservation placeholders are shown as such, and failed solves say so.

text
julia> batch_run
RunConditions
  temperature:   ConstantTemperature(293.15 K)
  concentration: 18.0 kg/m³
  crystals:      none
  operation:     BatchOperation()

julia> trajectory
CrystallisationSolution{MomentPopulation} — moments µ0 … µ4, success
  time:          0.0 … 28800.0 s (9 saves)
  concentration: 18.0 → 7.8 kg/m³
  d43:           ...
  ODE:           ... RHS evaluations, ... accepted / ... rejected steps

A FitResult lists the fitted parameter paths and values with the loss and, for Optimization.jl solvers, whether the optimiser reported convergence.

Seeds and distributions ​

julia
using Distributions
seed_population = DistributionInitialCrystals(
    LogNormal(log(12e-6), 0.2); mass_concentration = 0.25)
seeded_run = RunConditions(temperature = 293.15, concentration = 18.0,
    crystals = seed_population)
seeded_trajectory = simulate(crystal_model, seeded_run;
    solver = FiniteVol(meshsize = 400, lmax = 100e-6), saveat = [0.0, 3600.0])

Lengths are metres; solid mass concentration is kg/m³. Number weighting (NumberWeighted()) is the default. A volume-weighted source uses weighting = VolumeWeighted(); number_weighted(seed) provides explicit conversion. Conversion divides density by length cubed and fails when its number normalisation diverges. Explicit truncation belongs to the supplied distribution. Negative support is rejected.

Measured characteristics remain supported: LogNormalInitialCrystals requires mass, d43 and geometric standard deviation; GaussianInitialCrystals requires mass, d43 and standard deviation. In the model workflow they enter the same checked distribution builder. Mesh seeds report omitted number/mass fractions through seed_domain_diagnostics, and fail above mass_loss_tolerance (default 1e-4). Cell populations are integrated without rescaling lost mass. Mesh moment accuracy remains a numerical resolution question.

Solver and operation selection ​

Use MoM for compact scalar-rate moments, QMOM for quadrature reconstruction, seeded DQMOM for node-dependent growth, or FiniteVol/WENO for a resolved PSD. Unsupported combinations fail; solvers are never changed automatically. See Solvers for details and Operations for batch, MSMPR and fed-batch contracts. Supply operation to RunConditions.

Advanced numerical control ​

simulate(model, conditions; solver, saveat, algorithm, solve_options, callback_factory) shares the validated numerical solve policy with prepared fitting. Custom callbacks are constructed once per solve and compose with package callbacks. CrystallisationProblem(model, conditions; solver) builds the configured problem explicitly; simulate(problem; saveat) solves it. crystallisation_odeproblem and crystallisation_solution expose the generated SciML problem and physical reconstruction. Internal DQMOM coordinates differ from public weights and nodes; preserve that contract when solving directly.

runsimulation is the low-level interface for automatic differentiation and sensitivity work: it takes a flat or ComponentArray kinetic parameter vector and returns (problem, solution). kinetic_parameter_vector(problem) is the model's bound vector on paramaxis(problem), the default runsimulation(problem) uses. Use simulate for ordinary simulations.

A configured problem stores each value once: problem.model (material system and bound kinetic laws), problem.temp_profile, problem.initial_solvent_state (read the concentration with initial_concentration(problem)), problem.initial_population (the seeded solver population block, or nothing), problem.operation, problem.solver, problem.solvent_dynamics and problem.solid_mass_concentration_threshold. Material properties are read from the system, e.g. problem.model.system.crystal_density. The gas and Boltzmann constants are the module constants CriSTool.CRISTOOL_GAS_CONSTANT and CriSTool.CRISTOOL_BOLTZMANN_CONSTANT.
