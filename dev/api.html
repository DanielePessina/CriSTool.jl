API reference ​

The API is grouped by the decisions users make. Start with the simulation reference, then use the page for the subsystem you are changing or composing.

Named kinetic parameters ​

A law holds its parameter values as fields, like a Distributions.jl distribution: EmpiricalGrowth(growth_coefficient = 1e-9, growth_order = 2.0), read back as law.growth_order. paramaxis(law) names the parameters. The bounds and priors of an EstimationProblem select kinetic parameters using nested names such as growth.growth_coefficient. Unselected values stay fixed. ParameterSamples uses those same paths for joint uncertainty draws.

Cross-cutting contracts ​

  • Numeric SI: seconds, Kelvin, kg/m³, metres, rates in m/s.

  • solve(CrystallisationProblem(model, conditions, tspan), solver; saveat) returns the physical solution with t, retcode and named access sol[:concentration]; solve(remake(problem; p = values), solver) is the interface for autodiff and sensitivity work.

  • RunConditions hold temperature, initial concentration and solvent values, the seed and the operation; FromObservation reads a value from time-zero data.

  • Observable is a time series, including one-point measurements.

  • Transient fitting resolves FromObservation conditions from time-zero observations; those samples are not scored.

  • Likelihood requires supplied positive scored variances; noise is never fitted.

  • Fits return a new model and retain native backend diagnostics.

  • predict(result) reuses the fit's solver, mode and options; predicting from user samples requires an explicit solver.

  • Predictions retain failed draws; exclusion from summaries is explicit.

  • Automatic differentiation is forward mode: ForwardDiff and finite differences are tested; reverse mode (Enzyme, Zygote) is not supported in v1.

The lower-level solver engine still uses the internal block order nucleation, growth, dissolution, aggregation, breakage. Named model users do not assemble those vectors. Generated SciML and dispatch-based extension interfaces remain available for advanced users.

Custom nucleation families may subtype CriSTool.AbstractNucleationFunction by qualification/import; that base is not currently exported. The standard custom-rate signature is (fn, parameters, problem, state, t).
