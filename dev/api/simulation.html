Simulation and results ​

CrystallisationProblem follows the SciML problem/solve pattern: it holds the model, conditions, tspan and kinetic values p, and solve(problem, solver) chooses the numerical method. remake(problem; ...) copies it with fields replaced. Solutions expose sol.t, sol.retcode, successful_retcode(sol) and sol[:name].

CriSTool.CrystallisationProblem Type
julia
CrystallisationProblem(model, conditions, tspan, p = <model values>;
                       solvent_dynamics=default_solvent_dynamics,
                       solid_mass_concentration_threshold=1e-12)

One configured run, independent of the numerical solver: a CrystallisationModel under numeric RunConditions over the time span tspan = (t0, tf) in seconds. Solve it with solve(problem, solver; saveat); the solver (MoM(), QMOM(), FiniteVol(), ...) is chosen at solve time, as the algorithm is for an ODEProblem. Every value lives in exactly one place:

  • model::CrystallisationModel: material system and bound kinetic laws.

  • conditions::RunConditions: temperature, initial solvent values, seed and reactor operation. The seed is turned into a solver population at solve time.

  • tspan::Tuple{Float64, Float64}: integration span (s); t0 >= 0, tf >= t0.

  • p: kinetic parameters as one ComponentVector on paramaxis(problem) (blocks nucl, gr, diss, agg, br). Defaults to the model's bound values; remake(problem; p = values) replaces them, and its element type may be a dual number, so this is the differentiable entry point.

  • solvent_dynamics: callable (problem, state, time, growth) -> rates returning one derivative per named solvent variable. It receives the solve-time problem, whose state layout depends on the solver.

  • solid_mass_concentration_threshold::Float64: positive solid mass-concentration threshold (kg/m³) used by scalar signed-dissolution moment solvers to reset an extinguished population.

Universal constants are the module constants CRISTOOL_GAS_CONSTANT and CRISTOOL_BOLTZMANN_CONSTANT.

source
CommonSolve.solve Method
julia
solve(problem::CrystallisationProblem, solver::AbstractSolver; saveat=Float64[],
      alg=nothing, solve_options=(;), callback_factory=nothing) -> CrystallisationSolution

Integrate problem over problem.tspan with the population-balance solver (MoM(), QMOM(), DQMOM(), FiniteVol(), WENO()) and return its physical trajectory. saveat is a save step or a vector of save times inside tspan, as in OrdinaryDiffEq; by default every accepted step is saved. alg replaces the solver's default OrdinaryDiffEq algorithm (e.g. alg = Rodas5P()), solve_options passes further integrator options, and callback_factory(odeproblem) builds a user callback composed with the package callbacks. Inspect the result with sol.t, sol.retcode, successful_retcode(sol) and sol[:concentration].

CriSTool.CrystallisationSolution Type
julia
CrystallisationSolution{Population}

Physical result of a transient solve, shared by every solver. Solver-specific data live in population (MeshPopulation, MomentPopulation or QuadraturePopulation); everything else is common.

Fields:

  • t: saved times (s).

  • concentration: solute concentration trajectory (kg/m³), also available as solvent_state.concentration.

  • population: solver-specific population trajectory.

  • d10, d32, d43: moment-ratio sizes (m); zero for an empty population and NaN when the solver does not track the required moment.

  • moment2: second raw moment µ2 (m⁻¹).

  • solvent_state: named solvent-variable trajectories.

  • reactor_state: reactor-volume and size-boundary flow trajectories. Mesh solutions report signed lower/upper solid-mass flows in kg/s, positive out of the size domain.

  • final_state: the public numerical state at the last saved time.

  • ode_stats: ODE solver statistics.

  • retcode::ReturnCode.T: return code of the ODE solve; check it with successful_retcode(solution).

Named access does not depend on the solver: solution[:concentration], solution[:d43], solution[:d50q] or any solvent-state name index the trajectories, as do state_vars, size_metrics, reactor_vars and observable_values.

MomentPopulation

source
CriSTool.QuadraturePopulation Type
julia
QuadraturePopulation

Quadrature trajectory of a QMOM or DQMOM solve. moments has shape (2N, nt); nodes (m) and weights (particle number per m³) have shape (N, nt).

For QMOM the moments are the integrated state and the quadrature is reconstructed at every saved time; inactive nodes of an empty or rank-deficient rule are stored as zeros and diagnostics is a vector of QMOMInversionDiagnostics. For DQMOM the weights and nodes are the integrated state, the moments are derived from them, and diagnostics is a vector of DQMOMProjectionDiagnostics (or nothing for a dual-valued trajectory). quadrature(solution, index) returns one saved rule.

CriSTool.CrystallisationSteadyStateSolution Type

Result of relaxing an autonomous MSMPR to a numerically checked steady state.

steady.equilibrium holds the equilibrium values as one named tuple: t, concentration, d43, d32, other solvent and size scalars, and population vectors such as moments or numberdensity. The underlying one-sample physical solver result is steady.solution; observable_values, state_vars and size_metrics return its one-sample trajectories, so a steady result can be used wherever a transient result is expected.

Fields:

  • solution: one-sample CrystallisationSolution at the equilibrium time.

  • equilibrium: the same values as scalars (and population vectors).

  • residual, scaled_residual: native ODE right-hand side and its components multiplied by the residence time and divided by their state scale.

  • hydraulics: (; volume, inflow, outflow, residence_time).

  • product: (; dissolved_solute_flow, solid_mass_flow) outlet flows (kg/s).

  • diagnostics: convergence (converged, residual norms and limit), physical state, total-API balance and integration details, including the relaxation solve's own ode_retcode. For discretised solvers, population_density_diagnostics records the raw density minimum, peak scale, negative-cell count and machine-roundoff tolerance; accepted undershoots stay in the raw state and are labeled in physical_state_status.

  • ode_stats: from the relaxation solve.

  • retcode::ReturnCode.T: Success when the solver, residual, physical and balance checks all passed; otherwise the failed relaxation solve's own code, MaxIters when the residual did not converge within the relaxation horizon, or Failure when the physical state or flow balance is invalid.

CriSTool.CrystallisationSteadyStateProblem Type
julia
CrystallisationSteadyStateProblem(problem::CrystallisationProblem;
                                  u0=nothing, options=SteadyStateOptions())

Steady-state counterpart of a transient problem, solved with solve(steady_problem, solver): relax a constant, autonomous fixed-volume MSMPR to a stable steady state. u0 is an optional initial guess as a complete state vector in the solver's layout; without it the relaxation starts from the problem's conditions. options sets the relaxation horizon, residual tolerances and the autonomous declaration. The problem's tspan is not used: the relaxation runs from t0 over the relaxation horizon.

SciMLBase's SteadyStateProblem wraps an ODEFunction and an initial state, both of which depend on the solver here, so CriSTool owns this steady type.

source
CommonSolve.solve Method
julia
solve(steady_problem::CrystallisationSteadyStateProblem, solver::AbstractSolver;
      alg=nothing, solve_options=(;), callback_factory=nothing)
    -> CrystallisationSteadyStateSolution

Integrate the generated ODE of solver and stop early only when the scaled full-state RHS residual is within tolerance. The result's retcode reports the outcome; when it is unsuccessful (relaxation horizon, residual, physical constraints or total-API flow balance) the direct solve throws SteadyStateConvergenceError, which carries the unsuccessful result and its diagnostics. steady.equilibrium holds the equilibrium values (steady.equilibrium.concentration, .d43).

Opaque time profiles and user-defined kinetics require SteadyStateOptions(autonomous = true) as an explicit declaration that their behavior is time invariant. Batch and fed-batch problems remain transient solve(problem, solver) workflows.

source
CriSTool.SteadyStateOptions Type
julia
SteadyStateOptions(; relaxation_horizon=nothing, minimum_relaxation=0.0,
                    residual_reltol=1e-10, residual_abstol=1e-12,
                    residual_scales=nothing, autonomous=false,
                    balance_reltol=1e-5)

Settings for an MSMPR steady-state relaxation, validated on construction.

  • relaxation_horizon (s): longest relaxation time; nothing uses 100 residence times in a direct steady solve and the template ODE span in prepared inference.

  • minimum_relaxation (s): earliest time at which the residual stop may fire.

  • residual_reltol, residual_abstol: the run is converged when every scaled RHS component is at most their sum.

  • residual_scales: optional positive per-state residual scales.

  • autonomous: declare that opaque profiles and user kinetics are time invariant.

  • balance_reltol: accepted relative total-API flow-balance error.

CriSTool.CrystallisationFeed Type
julia
CrystallisationFeed(; concentration, crystals=nothing,
                     solvent_state=(;), transport=nothing)

One well-mixed slurry inlet. concentration (kg/m³) may be constant or a callable of time in seconds. solvent_state holds only the extra solvent species (each constant or a callable of time). crystals describes the fixed inlet population per m³ of feed, independently of the initial reactor seed; it must be fully numeric and is stored in its checked solver-ready form (_checked_seed_description), so downstream code never re-checks it. Solvent dynamics ​

default_solvent_dynamics is the default callable used by CrystallisationProblem. It updates the named :concentration solvent variable from the crystal growth rate and returns zero rates for any additional named solvent variables. Supply extra initial solvent values through RunConditions(solvent = (...)) and a custom solvent_dynamics callable (a CrystallisationProblem keyword, or problem_options in EstimationProblem) when the process includes coupled variables such as pH or volume.

Steady MSMPR solves ​

solve(CrystallisationSteadyStateProblem(problem; options, u0), solver) is the explicit steady-state route for a constant, autonomous MSMPROperation. CrystallisationSteadyStateProblem is CriSTool's own type because SciMLBase's SteadyStateProblem wraps an ODEFunction and initial state, which here depend on the solver. The solve relaxes the generated dynamics until the scaled residual covers every population and solvent-state component, then returns a CrystallisationSteadyStateSolution: scalar equilibrium values through steady.equilibrium (steady.equilibrium.concentration, .d43), product flows in steady.product, the full residual, a retcode, and physical and mass-balance diagnostics in steady.diagnostics (including the relaxation solve's own ode_retcode). Settings are passed as options = SteadyStateOptions(...); u0 is an optional initial guess in the solver's state layout. steady.retcode is Success when every check passes, MaxIters when the relaxation horizon ends before the residual converges, Failure when the physical state or flow balance is invalid, and the ODE code when the integration itself fails. An unsuccessful result is thrown as SteadyStateConvergenceError, which carries it in its solution field.

Batch and fed-batch runs are transient; use solve(problem, solver). Callable flow, feed, temperature, saturation, or kinetic profiles require SteadyStateOptions(autonomous = true) to declare that they are time invariant; the declaration is the caller's responsibility.
