Inference and uncertainty ​

EstimationProblem follows the SciML problem/solve pattern: it holds the model, experiments, selected parameters, loss and simulation settings, and solve(problem, alg) dispatches on the optimiser, while sample([rng], problem, sampler, n) draws from the posterior. The Turing methods sample([rng], problem, NUTS(), n_samples) and sample([rng], problem, NUTS(), MCMCThreads(), n_samples, n_chains) are defined by the CriSToolTuringExt extension (using Turing).

CriSTool.EstimationProblem Type
julia
EstimationProblem(model, experiments; bounds=nothing, priors=nothing, loss=GaussianNLL(),
                  solver=MoM(), mode=TransientMode(), problem_options=(;),
                  observable_order=nothing, observable_projections=(;), alg=nothing,
                  solve_options=(;), callback_factory=nothing)

Estimate the kinetic parameters of model named by bounds or priors from the measured experiments, scored by loss, with every run simulated by solver. solve(problem, alg) runs the estimation algorithm:

  • a Metaheuristics algorithm (DE(), NSGA2(), ...) or an Optimization.jl optimiser (LBFGS() from OptimizationOptimJL) searches inside bounds and returns a FitResult;

  • NUTS() (or another Turing sampler; requires using Turing) samples the posterior under priors and returns an InferenceResult;

  • ABCDE() or ABCDETurner() samples by approximate Bayesian computation under priors and returns an InferenceResult.

bounds are named (lower, upper) pairs and priors named univariate distributions, for example bounds = (growth = (growth_order = (1.0, 4.0),),). Supplying both lets one problem be optimised and sampled; they must then name the same parameters in the same order.

Construction resolves each experiment's conditions, validates bounds, priors and noise, and builds the reusable solve templates once. Time-zero observations consumed by FromObservation conditions are not scored. mode = SteadyMode(...) relaxes each run to its MSMPR steady state and needs numeric conditions to relax from. alg, solve_options and callback_factory configure the ODE solves as in solve(problem, solver). A likelihood loss (GaussianNLL) needs supplied measurement variances; noise is never fitted. remake(problem; kwargs...) rebuilds the problem with the given keywords replaced.

CommonSolve.solve Method
julia
solve(problem::EstimationProblem, optimiser; adtype=AutoForwardDiff(),
      parallel=EnsembleSerial(), kwargs...) -> FitResult

Optimise the selected kinetic parameters with an Optimization.jl optimiser (for example LBFGS() from OptimizationOptimJL), searching inside the bounds from the model's current values. adtype differentiates the loss; the remaining keywords (such as maxiters) go to the Optimization.jl solve. parallel = EnsembleThreads() solves the experiments of each loss evaluation (and so each ForwardDiff gradient) on threads; scores are reduced in experiment order, so the result is bitwise identical to EnsembleSerial().

source
CommonSolve.solve Method
julia
solve(problem::EstimationProblem, alg::Metaheuristics.Algorithm; parallel=EnsembleSerial())
    -> FitResult or Vector{FitResult}

Population search inside the bounds with a Metaheuristics algorithm (DE(), ECA(), NSGA2(), ...) run on a private copy, so alg, its options, status and RNG are not consumed. A scalar objective returns a FitResult; NSGA2 minimises each named observable objective and returns one FitResult per Pareto candidate. parallel = EnsembleThreads() evaluates the population on threads, each task on a private copy of the solve templates.

StatsBase.sample Method
julia
sample([rng], problem::EstimationProblem, sampler::AbstractABCSampler, n_particles; target,
       n_generations=128, stopping=AllGenerations(), parallel=EnsembleSerial()) -> InferenceResult

Sample the priors by approximate Bayesian computation (ABCDE() or ABCDETurner()) with n_particles particles, accepting particles whose loss is within the explicit finite discrepancy threshold target. rng makes the draws reproducible. The retcode is ReturnCode.Success when every particle reaches target, and ReturnCode.MaxIters when the generations run out first. parallel = EnsembleThreads() evaluates particles on threads, each on a private copy of the solve templates; the experiments of one discrepancy run serially.

CriSTool.FitResult Type
julia
FitResult

The result of solve(problem::EstimationProblem, optimiser), shaped like a SciML optimisation solution:

  • u: the selected parameter values as a flat vector, in selection order;

  • objective: the total loss at u;

  • retcode: a ReturnCode.T; check it with successful_retcode(result). It is Failure when the objectives at u are the failed-simulation penalty, even if the optimiser reported convergence;

  • parameters: the same values, named and nested like the bounds;

  • objectives: the named observable objectives whose sum is objective;

  • model: the model with the fitted values;

  • alg, original (the optimiser's own result) and estimation_problem.

TransientMode()

Integrate each run from time zero and compare the trajectory with observations at their measured times. This is the default for EstimationProblem and predict.

CriSTool.SteadyMode Type
julia
SteadyMode(; autonomous=false, relaxation_horizon=nothing, minimum_relaxation=0.0,
           reltol=1e-10, abstol=1e-12, residual_scales=nothing, balance_reltol=1e-5)

Relax each run to its MSMPR steady state and compare the steady values with every observation, regardless of observation time. Run conditions must be numeric. autonomous is the declaration of CrystallisationSteadyStateProblem (callable kinetic laws need autonomous = true); the other keywords are those of the steady solve, with the same defaults: without relaxation_horizon, each run relaxes for up to 100 residence times.

StatsAPI.predict Function
julia
predict(result; saveat=nothing, observables=nothing, parallel=EnsembleThreads())
predict(result, runs; saveat=nothing, observables=nothing, parallel=EnsembleThreads())

Propagate a fit or posterior through the same model, solver, mode and numerical options as the EstimationProblem it solved. Without runs, the fitted experiments are predicted at their observation times. runs may hold experiments (conditions resolved from their time-zero observations) or numeric RunConditions, which need saveat. A FitResult predicts its single fitted draw. By default (parallel = EnsembleThreads()) every (run, draw) pair is solved on threads, each task on a private copy of the prepared templates; EnsembleSerial() gives identical results on one thread.

source
julia
predict(model, runs, samples; solver, mode=TransientMode(), problem_options=(;),
        saveat=nothing, observables=nothing, alg=nothing, solve_options=(;),
        callback_factory=nothing, parallel=EnsembleThreads())

Propagate user-supplied joint kinetic draws. The solver is required so that a prediction never silently changes numerical method. alg, solve_options and callback_factory are the ODE solve settings accepted by EstimationProblem. Each draw is reused across all runs; noise is added only through measurement_samples.
